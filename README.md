# DataLink and Product Streamer Test Laboratory

A small software-verification laboratory by Quan Guo: resolve a synthetic data
identifier (DID), discover a download address, retrieve the product, and verify
the bytes independently. This repository contains the laboratory integration
code and tests, not a replacement implementation of SKA DataLink or Streamer.

## Test coverage and purpose

| Test group | Purpose |
|---|---|
| Login and endpoint health | Confirm protected access, origin rejection and reachable DataLink/Streamer services |
| DID and address discovery | Resolve four file DIDs plus one dataset DID; inspect VOTable descriptors and follow approved same-origin data URLs |
| File downloads | Compare four direct downloads and four Streamer downloads against independently generated bytes and SHA-256 values |
| Dataset delivery | Inspect the three-member TAR and verify each member without filesystem extraction |
| Partial data and errors | Check exactly 100 bytes, an unsatisfiable range, missing/denied/wrong-audience synthetic identities and malformed XML |
| Diagnostics and evidence | Inspect MIME, standardID and authentication challenge/discovery; save reports and address provenance |

Bootstrap routes are configured. This is not site-wide crawling or real SCAPI
service discovery. Wrong-audience and permission decisions are simulated.

## Run the external test

The existing test endpoint is `http://64.176.188.89:18080`. Obtain the disposable
laboratory password separately; it is deliberately absent from this repository.
The endpoint uses **unencrypted HTTP**, so do not use real SKA credentials or data.

```sh
git clone https://github.com/guotsuan/datalink-streamer-lab.git
cd datalink-streamer-lab
python3 lab/test_public_e2e.py --base-url http://64.176.188.89:18080
```

The script prompts for the password without echo. An existing private file can
instead be provided with `--password-file /absolute/path/to/private-password.txt`.
Never put the password itself in a command line, commit or issue.

Each run creates `lab/evidence/public-e2e/<UTC-time>-<id>/` with `report.md`,
`report.json`, `addresses.json`, VOTables, manifests and downloaded fixtures.
The expected fixture bytes are generated independently on the client; the server
manifest alone is not used as proof of correctness. Cookies and passwords are
excluded from the generated reports. Review any evidence before publishing it.

Exit codes: `0` = functional checks pass (review warnings); `1` = a failure or
dependency skip; `--strict` returns `2` when diagnostic warnings remain.
Use `--skip-server-suite` to omit the optional internal test run.

## Local regression tests

```sh
python3 -m unittest discover -s lab -p test_public_e2e_unit.py -v
# Requires FastAPI and HTTPX; after environment preparation:
lab/.venv/bin/python lab/test_public_gateway.py
```

These are offline helper tests, not a new live deployment acceptance run.
For deployment, follow [DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Recorded results

The **21 September 2026, 05:11 UTC** external run evaluated **33 checks** from
**41 HTTP requests**: **30 PASS / 3 WARN / 0 FAIL**. The separate internal suite
reported **14/15**, with one MIME diagnostic failure overlapping an external
warning. Details and limitations: [TEST_RESULTS.md](docs/TEST_RESULTS.md).

Three warning categories remain: response MIME, missing DataLink `standardID`
INFO, and an unusable external authentication challenge/discovery address.
Do not interpret these counts as IVOA certification or production readiness.

## Boundaries and safety

The official service processes, VOTables, byte streams and TAR creation are real.
DMAPI, IAM, PAPI and colocated-service discovery are fixtures. There is no real
SCAPI, Rucio, StoRM or federated SRCNet integration. Four synthetic files only.

The literals `lab-service-token`, `lab-denied-token`, `lab-raw-token`,
`lab-dm-token` and `synthetic-not-secret` are public mock values, not credentials.
Actual login passwords, password hashes, signing keys, cookies, logs and local
runtime configuration are excluded. Never expose the raw loopback services.
Publishing this repository does not open any server port or grant site access.

Evaluation references: [IVOA DataLink 1.1](https://www.ivoa.net/documents/DataLink/20231215/REC-DataLink-1.1.html),
[VOTable 1.4](https://www.ivoa.net/documents/VOTable/20191021/REC-VOTable-1.4-20191021.html),
[RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html), and
[SHA-256 / FIPS 180-4](https://csrc.nist.gov/pubs/fips/180-4/upd1/final).
The current Range check uses a Streamer POST, not RFC 9110 GET-range conformance.
